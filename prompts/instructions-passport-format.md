# Инструкция: формат итогового видео-паспорта

Передай этот файл агенту (как системные инструкции / context) ПЕРЕД основным промтом. Промт выдаёт транскрипт и данные видео, а эти инструкции фиксируют, КАК должен выглядеть итоговый паспорт.

Агент должен вернуть паспорт **точно** в этом формате: без вступления, без пояснений, без Markdown-обёрток — только содержимое паспорта.

---

## 1. Структура паспорта

Паспорт состоит из четырёх блоков в строгом порядке:

1. **YAML-frontmatter** — SEO-метаданные и модерация (между `---`).
2. **`# Таймлайн и монетизация`** — сцены с точками монетизации.
3. **`# Музыка`** — распознанные треки.
4. **`# Знаменитость`** — распознанный голос.

---

## 2. YAML-frontmatter (шаблон)

```yaml
---
video_id: "Rv_<id>"
domain_type: <домен>
brand_safety_score: <0-100>
target_audience: ['категория1', 'категория2', ...]
seo_title: "<заголовок до 100 символов>"
seo_tags: ['тег1', 'тег2', ...]
trending_cluster: "<кластер>"
auto_playlists: [{'id': 'pl_...', 'order_index': N, 'reason': 'почему'}, ...]
ad_targeting_keywords: ['ключ1', 'ключ2', ...]
moderation:
  age_rating: "<0+|6+|12+|16+|18+>"
  verdict: <approved|flagged|rejected>
  categories_flagged: ['категория1', ...]
  flags: <количество флагов>
  summary: "<1-2 предложения обоснования>"
---
```

### Правила полей

- **video_id** — берётся из промта без изменений.
- **domain_type** — один из: `tech_review | product_review | review | how_to | how_to_repair | diy | diy_crafts | game_review | travel_vlog | entertainment | movie_review | true_crime | education | podcast | lecture | stream | unknown`.
- **brand_safety_score** — целое 0–100, равно значению из moderation.
- **seo_title** — до 100 символов. Для `tech_review` — конкретные модели/бренды; для `travel_vlog` — страна/город; для `game_review` — название игры.
- **seo_tags** — 5–10 тегов.
- **trending_cluster** — компактный кластер вида `tech/gadgets/phones`, `gaming/reviews/action`, `travel/expat/...`.
- **auto_playlists** — 2–3 плейлиста: уникальный `id` (`pl_...` или слаг), `order_index` (0-первый), `reason`.
- **ad_targeting_keywords** — максимально полно: конкретные товары, бренды, услуги из видео.
- **moderation.age_rating** — `0+|6+|12+|16+|18+`.
- **moderation.verdict** — `approved` / `flagged` / `rejected`.
- **moderation.categories_flagged** — категории из: `profanity`, `hate_speech`, `violence`, `nsfw`, `drugs_weapons`, `self_harm`, `misinformation`, `controversial_figure`, `copyright_music`. Пустой список `[]`, если нарушений нет.
- **moderation.flags** — ТОЛЬКО количество (целое число), не сам список флагов.
- **moderation.summary** — 1–2 предложения: вердикт + ключевые флаги + допуск к рекламе.

Списки в frontmatter оформляй в одну строку со списками в одинарных кавычках (как в нативном выводе системы): `['a', 'b', 'c']`.

## 3. Таймлайн и монетизация

Блок открывается заголовком:

```
# Таймлайн и монетизация
```

Каждая сцена — секция `##`, разделённая `---`:

```
## [MM:SS - MM:SS] <краткое описание сцены>
* **Спикер:** <спикер>
* **ASR Context:** "<текст сегмента>"
* **[ECOM_ITEM]** — Поисковый запрос: "<товар>"
  * Уверенность: NN%
* **[AD_SLOT]** — Таргетинг: "<ключевые слова>"
  * Контекст: <почему здесь>
* **[CLIP_CANDIDATE: MM:SS - MM:SS]**
  * Хук: <заголовок-крючок>
  * Виральный потенциал: <low|medium|high>

---
```

### Правила сцен

- **Заголовок сцены**: `## [MM:SS - MM:SS]` (тайм-коды из транскрипта) + описание сцены одним-двумя предложениями, отражающее содержание сегмента. Если для сцены нет тайм-кодов — префикс `[MM:SS - MM:SS]` опускается (заголовок начинается сразу с описания).
- **Спикер**: имя из транскрипта.
- **ASR Context**: дословный текст сегмента в кавычках (максимум ~200 символов).
- **Покрытие**: паспорт должен покрыть всё видео от первой до последней сцены. Одна сцена = один сегмент транскрипта (соседние смыслово связанные сегменты можно объединять).
- **Если в сцене нет точек монетизации** — строки монетизации просто не выводятся (заголовок + спикер + ASR Context остаются).

### Форматирование точек монетизации

Каждый тип имеет свой формат строки:

| Тип | Формат |
|---|---|
| `ECOM_ITEM` | `* **[ECOM_ITEM]** — Поисковый запрос: "<товар>"` + `  * Уверенность: NN%` |
| `AD_SLOT` | `* **[AD_SLOT]** — Таргетинг: "<ключевые слова>"` + `  * Контекст: <почему>` |
| `MUSIC_TRACK` | `* **[MUSIC_TRACK]** — <исполнитель — трек>` + `  * Контекст: <почему>` |
| `ARTIST_MERCH` | `* **[ARTIST_MERCH]** — <мерч>` + `  * Контекст: <почему>` |
| `EVENT_TICKET` | `* **[EVENT_TICKET]** — <билеты: исполнитель — город>` + `  * Контекст: <почему>` |
| `CELEBRITY_APPEARANCE` | `* **[CELEBRITY_APPEARANCE]** — <имя знаменитости>` + `  * Контекст: <почему>` |

`ECOM_ITEM` — единственный тип с **уверенностью в процентах** (0–100%). Остальные — с контекстом.

### CLIP_CANDIDATE

Выводится отдельным блоком ТОЛЬКО если сцена подходит для нарезки/Shorts (лайфхак, ошибка, неожиданный поворот, виральная фраза):

```
* **[CLIP_CANDIDATE: MM:SS - MM:SS]**
  * Хук: <заголовок-крючок>
  * Виральный потенциал: <low|medium|high>
```

Хук — короткий цепляющий заголовок (не полное описание сцены). В `CLIP_CANDIDATE` **не дублируй** другие типы монетизации — кандидат на клип сам по себе является точкой монетизации.

## 4. Музыка

Блок открывается заголовком `# Музыка`. Список распознанных треков:

```
# Музыка

* **<артист> — <трек>** (уверенность: NN%) — <жанр> · <альбом> · <год>
```

- Треки берутся из поля «Музыка на фоне» в промте.
- Если треков нет — выведи ровно: `_Треки не найдены_`.

---

## 5. Знаменитость

Блок открывается заголовком `# Знаменитость`:

```
# Знаменитость

* **<имя>** — <профессия> (уверенность: NN%)
```

- Данные берутся из поля «Известные личности» в промте.
- Если знаменитость не распознана — выведи ровно: `_Знаменитость не распознана_`.

---

## 6. Чек-лист перед ответом

- [ ] Frontmatter между `---`, все поля заполнены, `flags` — число.
- [ ] Таймлайн покрывает всё видео, тайм-коды в `MM:SS`.
- [ ] `ECOM_ITEM` — с процентом, `AD_SLOT` и остальные — с контекстом.
- [ ] `CLIP_CANDIDATE` — отдельным блоком, без дублирования типов.
- [ ] Блоки «Музыка» и «Знаменитость» присутствуют (с `_Треки не найдены_` / `_Знаменитость не распознана_` при отсутствии данных).
- [ ] Ничего, кроме паспорта: без вступления, без пояснений, без обёрток.
